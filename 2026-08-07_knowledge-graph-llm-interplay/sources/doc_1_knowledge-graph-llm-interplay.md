### ナレッジグラフの基礎技術

- ナレッジグラフ: さまざまな「知識」の関係（つながり）をグラフ構造で表したデータベース。定義は人・コミュニティによって異なることに留意。
- Linked Data（LD）: Webの仕組み（URI/URL）を用いて相互接続されたデータ。
- Linked Open Data（LOD）: オープンな形式で公開されたLinked Data。
- RDF（Resource Description Framework）: 主語-述語-目的語のトリプル（3つ組み）でグラフ構造を表現するデータモデル。

### RDFトリプルの具体例

大阪電気通信大学を例にすると、以下のようなトリプルで表現される。

- 主語: 大阪電気通信大学（URI: `http://www.wikidata.org/entity/Q7105556`）
- 述語: 設立日、位置する行政区、国、職業（分類）など
- 目的語: 1941年（リテラル）、寝屋川市（リソース）、日本（リソース）、大学（分類）

### SPARQLクエリの例（Wikidata: 日本の政治家の出身都道府県ランキング）

```sparql
SELECT ?pref ?prefLabel (count(?s) As ?c) WHERE {
  ?pref wdt:P31 wd:Q50337;  #分類＝都道府県
  wdt:P429 ?code.
  ?s wdt:P27 wd:Q17;  #国籍＝日本
  wdt:P106 wd:Q82955;  #職業＝政治家
  wdt:P19/wdt:P131* ?pref.  #出身
  SERVICE wikibase:label {
    bd:serviceParam wikibase:language "[AUTO_LANGUAGE],en"
  }
}
GROUP BY ?pref ?prefLabel ORDER BY DESC(?c)
```

職業条件を「内閣総理大臣」に変えたい場合は `wdt:P39 wd:Q274948;` という1行を追加するだけでよい。

### オントロジーとは何か

- 定義: 「対象世界をどのように捉えたか？（概念化したか）」を計算機と人間が共有できる形で明確化・体系化したもの。
- 3つの主要機能: ①ナレッジグラフの記述に用いる語彙（分類や関係の種類）を提供する、②概念の共通性と相違点（意味）を明確にする、③統一した語彙により知識の統合・相互利用を可能にする。
- 具体例（車両の概念化）: 単に「二輪車、自動二輪、自転車」と列挙するだけの概念階層と、「二輪車→車輪の数＝2」「自動二輪→動力源＝エンジン」「自転車→動力源＝人」のように定義を加えた概念階層を比較すると、後者は各概念の意味の違いが明示化され、システムが正確に処理できるようになる。

### ナレッジグラフの利用例

- Wikidata: 約1億項目を保有するオープンな知識グラフ。SPARQLで検索できる。
- DBpedia: Wikipediaから自動抽出したナレッジグラフ。
- Google Knowledge Graph: 検索結果の「ナレッジパネル」表示に利用。
- KGQA（Knowledge Graph Question Answering）: 質問の意図解析→適切なエンティティ・プロパティの同定→グラフトラバーサル（リソース間のリンクをたどる）→結果の抽出と自然言語化、という流れで動作する。説明可能な根拠に基づく正確な質問応答が可能という利点があり、これがLLMのハルシネーション・回答根拠の暗黙性という課題との補完関係を形成する。
  - 例1: 「『天気の子』の監督は？」→「『新海誠』です」
  - 例2: 「『大阪電気通信大学』の所在地は？」→「『寝屋川市』です」
- ナレッジグラフ推論チャレンジ2018-2024: 推理小説KG構築部門・一般部門などがあり、Llama 2やGPT-4を利用した自動構築実装の応募もある。

### ISWC2023・JSAI2024の動向

- Weikum氏のキーノート主張: 「LLMはKGに取って代わるものではなく、補完的な利用が可能」。
- JSAI2024企画セッションのテーマ: 生成AI時代でのナレッジグラフの活かし方、両技術のシナジー構築、オープン/クローズド情報の取り込み。

### KGとLLMの相互利用：6つの形態

1. **KG vs. LLM（性能比較）**: 同一タスクでの両者の性能を比較する。例: 大阪電気通信大学のキャンパス所在地について、Wikidataは正確に「寝屋川・四條畷」と答えるが、ChatGPT 4o miniは「枚方市には無い」と誤り、ChatGPT 4はより正確に補足した。KGQA研究ではF1スコアで0.5〜0.9、Accuracyで0.2〜0.9など性能差が報告されている。
2. **LLM for KG（KGを用いたLLMのファクトチェック）**: KGから得た事実情報とLLMの生成内容を比較検証する。日本の大学798件など18,167インスタンスを対象にWikidataの事実とChatGPT3.5の回答を比較した大規模調査では、一致率が0.6〜32.7%と領域によるばらつきが大きい結果になった。
3. **LLM学習にKGを利用**: 知識グラフを用いて言語モデルの学習に使うテキストを生成するアプローチ。
4. **KGをLLMの外部知識として利用（Graph RAG）**: 質問文→①KGで検索→②LLMで検索→③KG/LLMの組み合わせ→④最終回答生成、という流れ。必要な技術要素は次の4つ。
   - 使用するKG: 既存KG（Wikidata、DBpedia等のLOD）か、独自KG（手作業構築、DB変換、テキスト抽出）か。
   - KGの検索方法: グラフパターン一致（SPARQL、Cypher等）、グラフ構造の探索と距離計算、グラフ埋め込み（ベクトル化）による類似判定。
   - KGとLLMの組み合わせ方法: 検索結果の比較・総合判定、KG検索結果からプロンプト生成、KG検索結果をテキスト化してLLM入力、ベクトル化して統合（RAG等）。
   - 使用ツール: クエリ言語（SPARQL、Cypher）、RDF DB（Apache Jena Fuseki、Virtuoso等）、グラフDB（Neo4j、Amazon Neptune）、Graph RAG実装（LangChain+Neo4j、Microsoft GraphRAG等）。
5. **KG for LLM（LLMをKG利用のインターフェースに）**: ①自然言語インターフェース（KG検索に必要なクエリをLLMが生成）、②結果の文章化（KGの検索結果をLLMで自然な文章に変換）の2つの活用方法がある。
6. **LLMを用いたKG/オントロジーの自動構築**: Text2KGBenchでは、テキストからオントロジーに基づいたナレッジグラフを自動構築し評価している。オントロジー学習（OL）では、LLMにZero-Shotプロンプティングを行い「用語の分類・分類の発見・非分類関係の抽出」といった主要タスクを評価する。

### まとめ

- ナレッジグラフとLLMは競合関係ではなく補完関係にあり、KGの「説明可能性・正確性」とLLMの「自然言語理解・生成力」を組み合わせることが今後の主要な方向性。

## 補足で確認した情報（WebSearchで確認）

- Microsoft GraphRAGは、Leiden法（Louvain法を改良したコミュニティ検出アルゴリズム）を用いて、抽出したエンティティ・関係のグラフから階層的なコミュニティ（意味的にまとまったエンティティ群、いわば「トピック」）を検出する。
- この階層構造を使うことで、「広い概観を答えるグローバル検索」と「特定の詳細を答えるローカル検索」の両方に対応できる（Level 0が元のグラフ、Level 1以降は検出したコミュニティを集約して再度Leiden法を適用し、より大きなコミュニティを見つける）。
- 出典: https://www.microsoft.com/en-us/research/ , https://github.com/microsoft/graphrag , https://arxiv.org/abs/2404.16130 （"From Local to Global: A Graph RAG Approach to Query-Focused Summarization"）
